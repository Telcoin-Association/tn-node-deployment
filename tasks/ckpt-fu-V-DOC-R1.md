## Report

1. error. Web UI, "Long-running actions": "During the epoch wait nothing has changed yet, so stopping there leaves the node as it was." True for an update (update-node makes backups, update_epoch_wait, then stops and swaps). False for a config save: edit-config.sh run_set writes the edit (set_field) before edit_restart -> edit_epoch_wait, and the EXIT trap edit_on_exit only releases the lock and sends done; it does not call edit_restore_backups. A save aborted during the wait (tab left, server kills the script) leaves the edited launch file / parameters.yaml / peers file on disk, unapplied and unverified; the next restart or reboot picks it up with no rollback. Fix: "During an update's wait nothing has changed yet. A config save has already written the change: stopping during its wait leaves it on disk, to take effect unchecked at the next restart; save again or set the old value back." (Or make edit_on_exit restore the backups when the restart never ran.)
2. warn. "Restarts and the epoch boundary": "Every script that restarts the node checks first: ..." migrate-node-naming.sh stops the legacy unit and starts the unified one with no wait (stop_legacy `systemctl stop "telcoin-${ROLE}"`, then `systemctl start "$UNIFIED_SERVICE"`; no tn_wait_restart_window in the file). The Node Manager UI restarts at once: Start/Stop/Restart buttons (ui/server.py api_service: `sudo /bin/systemctl <action>`), trace toggles and node-name change (helper cmd_tracing_enable/cmd_tracing_disable/cmd_set_hostname: `systemctl restart --no-block`). Fix: "These wait first: ..." and add that migrate-node-naming.sh and those UI actions restart at once, like systemctl.
3. warn. "setup-node flags", last paragraph: "In --json mode every input is checked before setup requires root. ... a keygen without --address ... stops the run". The missing --address is refused only in step_generate_keys (`setup_fail "--address is missing: keygen needs the node's execution address ..."`), after json_require_root, preflight (dependency installs, possibly a 20-40 min source build) and step 4 (service user, directories, .node-meta). init_node_inputs says "An empty multiaddr or address is left to the step that needs it." Fix: drop "a keygen without --address" from the before-root list and say it is refused at key generation (or add a pre-root check in run_json_mode).
4. warn. "What rpc-enable does", last paragraph: "With a lib/common.sh older than 1.6.0, rpc-enable warns and runs without the epoch wait ...; older than 1.5.0, it also warns that it runs without the update lock." The wait is gated on tn_wait_restart_window + tn_local_rpc_url (install-caddy.sh caddy_lib_has), both added in lib 1.5.0 (1e2d2f1). Fix: "older than 1.6.0: without adding --ws and with the python3 editor; older than 1.5.0: also without the epoch wait and the update lock."
5. warn. "Editing the configuration": nothing says that Refresh chain configs (item 11) copies the network's parameters.yaml over the node's (refresh_chain_configs `cp "${chain_config_src}/parameters.yaml" "${node_data_dir}/"`), which drops allow_private_forward_targets set by item 10 / --set. Fix: "Refresh chain configs replaces parameters.yaml; set allow_private_forward_targets again afterwards."
6. warn. "Converting a unit-started node to a start wrapper" names only older Docker installs. Installs from before v1.1.22 (87379f3, 2026-05-19) also start binary/source nodes from the unit (`Environment="TN_BLS_PASSPHRASE=<value>"`, `ExecStart=<binary> node ...`; git show 87379f3^:setup-validator.sh). edit-config refuses bootstrap_peers for them too (launch file *.service) and the docker-run procedure does not fit. Fix: name them; give the binary variant (wrapper `exec /opt/telcoin/telcoin-network node ...`, passphrase from $CREDENTIALS_DIRECTORY, drop the Environment= line) or say to re-run setup-node.sh.
