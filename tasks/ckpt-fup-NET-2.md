## Docs notes
- Lint: `tools/check-network-hits.sh [--list] [ROOT]` (ROOT default: the repository the tool lives in; no git needed). Exit 0 clean (stderr "check-network-hits: clean, N annotated hit(s) in M file(s) scanned"); 1 unannotated hits (stdout `FILE:LINE: <trimmed line>` each, plus a summary on stderr); 2 for an unknown option, two ROOTs, a ROOT that is not a directory, a missing lib/testnet-addons.env, a missing or non-literal value of one of its four names, or a scanned file that is missing or unreadable. `--list` prints every hit as `FILE:LINE: <reason> -- <line>` (reason "unannotated" when none) and the patterns on stderr. `--help`.

- Scope: lib/*.sh (not lib/wgvpn/), root *.sh, ui/server.py, ui/telcoin-ui-helper.sh, ui/install-ui.sh (added in the follow-up), ui/static/index.html, observability/config.alloy. Not: common/, tools/, tests, CHANGELOG*, tasks/, followup.md, docs/, *.md, lib/testnet-addons.env, *.sha256, lib/release-keys/README.
- Marker: `network-gated:` right after a comment opener (`#`, `//`, `<!--`, `/*`), then a reason with a letter or digit; `-->`/`*/` are not part of the reason. A hit passes when its own line carries the marker, or when the line right above it is a marker line: a line that is nothing but the marker comment (it starts with the marker, and a `<!--` or `/*` marker closes on that line with only blanks after the `-->` or `*/`). A trailing marker covers its own line only. Forms: shell/Python `# network-gated: <reason>`, JavaScript/Alloy `// network-gated: <reason>`, HTML `<!-- network-gated: <reason> -->` (HTML outside scripts only).
- Where a marker cannot go: inside a JavaScript template literal an HTML marker is rendered into the page (a comment node) and `//` is plain text, so move the testnet text out of the template into a constant on a line below a `//` marker line; inside a heredoc a marker is written into the file the heredoc makes, so reword the line to name no testnet instead; inside a Python docstring a marker is docstring text, so put the name on the docstring's first line and the marker comment between `def` and the docstring. Inside the --help header of setup-node, edit-config and update-node a marker line is fine: the help printer leaves it out.
