# v0.16.0-adiri round (October 2026)

This round makes the operator-side changes for the adiri move to v0.16.0-adiri. The release is telcoin-network `d72cc2bc`, published as image `us-docker.pkg.dev/telcoin-network/tn-public/adiri:v0.16.0-adiri` for linux/amd64 with index digest `sha256:b905b0982e87d5ca608e2f29192d0c5582793ae0043630074cddb9be1162ffea`. The git tag is pushed and peels to d72cc2bc. The first start of v0.16 migrates `consensus-db/epochs` one way (pack v1 to v2), and v0.15 cannot reopen it. So the public updater must stop auto-rolling the binary back across that line.

## What changed

### update-node 1.2.1

An apply is one-way when it goes from a release below 0.16.0, or from a running release that cannot be read, to 0.16.0 or later, or to a branch or commit. On a one-way apply, update-node:

- warns before the stop;
- checks free space against twice the largest `epoch-N`;
- asks for a snapshot in interactive mode;
- waits 600 s for the first start, unless `TN_UPDATE_VERIFY_TIMEOUT` is numeric (a leading zero is no longer read as octal);
- never rolls back on failure. It leaves the node as it is, clears the pending state, keeps the version marker and prints the restore steps.

In `--json` mode the failed `done` is `{"ok":false,"phase":"apply","rolled_back":false,"storage_migration":true,…}`. It is the same when the apply is cut short after the new release started. `--check` gains `"storage_migration"`, and both prepare paths emit the one-way `warn`.

Updates that do not migrate keep the 45 s window and the rollback.

## Interface contract with the fleet driver

The fleet driver lives in adiri-genesis. It relies on these points:

- `--check` reports `"storage_migration":<bool>`.
- A failed one-way apply emits `error`, then exactly one `done` with `rolled_back:false, storage_migration:true`. The node is left running.
- A numeric `TN_UPDATE_VERIFY_TIMEOUT` counts as explicit.

Phase 0 of the fleet roll requires `SCRIPT_VERSION ≥ 1.2.1` on followers, and followers pull it from `main`. So the fleet roll waits for this round to merge, plus about 5 minutes for the raw CDN.

- Interactive "Prepare only" gives no one-way warning.
